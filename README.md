# AgentTx

**AgentTx makes the kernel — not the network interface — the point at which an
AI agent's actions become real.**

`tx_begin` · `tx_commit` · `tx_abort`. Inside a transaction, writes divert into a
copy-on-write overlay in the agent's private mount namespace, and outbound
effects are captured in a kernel write-ahead log rather than emitted. An
`int8`-quantised classifier runs inside an eBPF LSM hook and sorts each effect
into four classes: reversible, deferrable, compensable, irrevocable.

See **[PROPOSAL.md](PROPOSAL.md)** for the argument, **[paper/](paper/)** for the
full write-up, **[READING-LIST.md](READING-LIST.md)** for the literature.

## Layout

```
include/agenttx.h    THE CONTRACT. Change only via a `contract-change` PR
                     with all four approvals (WORKFLOW.md Rule 1).
src/core/            P1  transaction core
src/fs/              P2  copy-on-write storage
src/bpf/             P3  effect interception
src/policy/          P4  in-kernel inference
src/stub/            one fake per provider, so any one person can run the
                     whole system alone from week 3 (WORKFLOW.md Rule 2)
tools/vm/            identical environment for all four: kernel config
                     fragments, build, boot, gdb, and `doctor.sh`
tools/harness/       P4's userspace pipeline; runs anywhere with python3
tools/bench/         the results CSV contract, and its enforcer
tests/p1..p4/        one owner per directory
docs/journal/        one file per person: panics, causes, fixes
```

Nobody edits another person's directory. The only shared files are
`include/agenttx.h`, `Makefile` and `Kbuild`, and all three are change-controlled.

## The two build modes

```bash
make STUB=1    every provider faked; the system loads and the demo runs
make           the real thing; Friday integration day
```

The stub build is what makes the 51 fragments parallel instead of sequential.
A fragment that cannot be tested against stubs was cut wrong.

## Before you trust a number

The classifier pipeline currently trains on **synthetic** traces generated by
`tools/harness/synth.py`. Every record carries `label_source="synth"`, `train.py`
prints a banner saying the results are not results, and `features.py
--exclude-synth` drops them the moment real captures exist. The honest claim
available today is that the pipeline runs end to end — which is exactly what
fragment P4-04 exists to establish.

The project's own gate (PROPOSAL.md, weeks 3–4) is measured by
`tools/harness/measure_gate.py`, which **needs no kernel work at all**. Run it in
week 1.
