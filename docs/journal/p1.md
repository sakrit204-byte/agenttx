# P1 journal

## 2026-09-16 --- P1-03..P1-10 verified in the guest

Kernel 6.12 debug profile (KASAN inline + lockdep + BTF), module loaded over
9p, driven by `tools/harness/txctl`. `tests/run.sh` in the guest: **8 passed,
0 failed**, and `dmesg | grep -cE 'BUG:|KASAN|WARNING:|circular locking'`
returns 0.

Three real bugs, all found by tests failing rather than by reading the code.

### 1. A transaction did not outlive the process that opened it, and its children were not inside it

`t02` and `t03` failed on their first run in the guest. `txctl begin` printed
an id, and `txctl stat` one line later reported `none`.

That was P1-08 working perfectly: the table is keyed by tgid, `txctl begin`
exits immediately, and the exit hook aborts the transaction of a process that
died. The tests were wrong about the lifetime.

But the failure pointed at something the tests were right about. With tgid
keying and no inheritance:

* a process that calls `tx_begin` and then forks has a child which is **not**
  inside the transaction --- its syscalls miss every hook, and the sandbox has
  a hole exactly the shape of *"the agent ran a subprocess"*;
* and since the agent must exit before its exit status can serve as the
  verification signal, the supervisor could never commit anything.

Fix: membership is inherited. `tx_current_id()` walks `real_parent` up to
`TX_ANCESTOR_MAX` (16) frames. Bounded, because an unbounded walk in a hook
that runs on every syscall is a denial of service. P1-12 replaces it with a
`task_struct` pointer copied at `copy_process()`, which is O(1) and exact;
this is the version that does not cost a kernel rebuild per iteration.

### 2. Inheritance immediately opened a privilege escalation

`tx_check_commit_authority()` refused a commit from the transacting process by
comparing tgids. The moment descendants were inside the transaction, the agent
could defeat that with one `fork()`: the child's tgid differs from the
owner's, so the comparison passed and the child committed. That is the
premature-commit attack plus one line of attacker code.

Fix: authority is a **membership** question, not an equality one.
`tx_ctx_covers_current()` walks the same ancestry and refuses anyone inside
the transaction at any depth. `t05` asserts it at depth 3.

### 3. `TX_IOC_STAT` reported dead and imaginary transactions as healthy

An explicit `tx_id` that resolved to nothing fell into the "not in a
transaction" path and returned a zeroed struct with success. So a caller could
not distinguish *finished* from *never existed* from *I made this number up* ---
every one of them answered `state: none`. `t03` caught it.

Fix: `TX_ID_NONE` still means "am I in a transaction?" and still answers "no"
without an error, because the harness polls it constantly. An explicit id that
does not resolve is `-ENOENT`.

### The process shape `txctl run` needs, and why it is three processes

```
txctl            supervisor. Registers, decides, commits.
 └── holder      calls tx_begin. OWNS the transaction.
      └── CMD    the agent. Inside it by inheritance.
```

Two processes does not work in either arrangement. If `txctl` opens the
transaction it is inside its own transaction and the kernel correctly refuses
its commit. If `CMD` opens it, the transaction dies when `CMD` exits --- and
`CMD` must exit before its status can be the verification signal. The holder
exists only to outlive the agent. It is four lines and it is the difference
between the model working and not.

A fourth bug lived here too: `txctl run` never registered as supervisor, so
`tx_begin` recorded `supervisor_pid == 0` and every commit was refused with
*"no supervisor registered"*. Correct fail-closed behaviour, useless client.
Registration has to happen **before** `tx_begin`, because `tx_begin` is what
stamps the supervisor onto the transaction.

### What is still not tested here

`DOOMED` is unreachable from userspace: it needs `tx_note_class(TX_IRREVOCABLE)`,
which only a real classifier in a real hook calls. So the edge that carries the
whole irrevocability argument is asserted *indirectly* --- `tx_state_selfcheck()`
runs at `module_init` and refuses to load if `DOOMED -> ABORTING` is ever
reachable, so "the module loaded" is the proof. The direct test belongs to P3.
